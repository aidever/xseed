# xseed 发布与运维

| 项目 | 内容 |
|---|---|
| 依据 | [详细设计](03-详细设计说明书.md) §1.13 注册中心、§4.2 节点配置、§7.1 节点容量 |
| 适用 | 版本发布者、注册中心维护者、社区节点运营者 |

## 1. 发布版本

推送 `v*` 标签即发布，CI 自动完成：

| 产物 | 说明 |
|---|---|
| `xseed-<版本>-linux-amd64.tar.gz` / `linux-arm64.tar.gz` | `xseed-agent` 与 `xseed-node`，musl 静态链接，任何 Linux 发行版可直接运行 |
| `xseed-<版本>-windows-amd64.zip` | `xseed-agent.exe`，托盘程序 |
| `SHA256SUMS` | 校验和 |
| `ghcr.io/aidever/xseed:<版本>`、`:latest` | Docker 镜像（amd64 / arm64）；`main` 分支每次推送更新 `:main` |

```sh
git tag -a v0.2.0 -m "v0.2.0"
git push origin v0.2.0
```

各架构的二进制在原生 runner 上编译（arm64 使用 `ubuntu-24.04-arm`），镜像直接复制编译好的二进制，不再用 QEMU 模拟编译。

### 1.1 Windows 版

- 双击运行，托盘出现星轨图标；首次运行自动打开浏览器进入设置向导。双击图标或菜单“打开 xseed”打开管理界面，“退出”结束程序。
- 数据目录 `%APPDATA%\xseed`（配置、数据库、加密密钥、日志 `xseed-agent.log`）。
- 管理界面默认只监听 `127.0.0.1:7731`，只有本机可以访问。
- 开机自启：把 `xseed-agent.exe` 的快捷方式放进“启动”文件夹（`Win + R` 输入 `shell:startup`）。
- 启动失败（例如端口被占用）会弹窗说明原因。

## 2. 注册中心

注册中心发布一份签名的节点清单，内含节点、站点定义与公共 tracker 列表。小助手与节点只接受内置公钥（或用户在“设置”中追加的公钥）签名的清单，并拒绝版本号回退。

### 2.1 仓库结构

```
xseed-registry/
  nodes/<名称>.json        每个节点一个文件：xseed-node manifest 的输出
  sites/<站点ID>.json      站点定义
  public-trackers.txt      公共 tracker 主机，每行一个（# 开头为注释）
  NOTICE                   站点定义来自 PT-depiler（MIT）的版权声明
```

站点定义（字段为明文）：

```json
{
  "id": "example",
  "name": "Example",
  "domains": ["example.org"],
  "tracker_hosts": ["tracker.example.org"],
  "p2p": "unknown",
  "allow_skip_check": true,
  "download_template": null
}
```

- `p2p`：站长态度，`allow` / `deny` / `unknown`。改为 `deny` 后，小助手收到新清单即关闭该站，未完成的任务取消。
- `download_template`：下载地址模板，如 `https://example.org/download.php?id={id}&passkey={passkey}`；主机必须是该站自己的域名，否则小助手忽略。为空时按通用规则推导。
- `allow_skip_check: false` 时加入下载器不跳过校验。

### 2.2 签名密钥

```sh
xseed-node registry keygen registry.key       # 打印公钥 ed25519:…；私钥文件权限 0600，不覆盖已有文件
```

- 生成两把：**主密钥**日常签名，**备用密钥**离线保存（不同介质、不同地点）。两把公钥都写入 `crates/xseed-transport/src/registry.rs` 的 `OFFICIAL_KEYS`，随版本发布。
- 主密钥泄露或丢失：用备用密钥签名下一份清单（立即生效，因为它本来就受信任），并在下一个版本中把 `OFFICIAL_KEYS` 换成“备用 + 新备用”。
- 私钥绝不进仓库、不放 CI；签名在维护者本机进行。

### 2.3 发布清单

```sh
xseed-node registry build xseed-registry/ registry.json      # 校验节点 ID、node_tag 唯一、站点 ID 唯一；版本号取当前时间
xseed-node registry sign registry.key registry.json          # 写出 registry.json.sig
xseed-node registry verify registry.json ed25519:<主公钥> ed25519:<备用公钥>
```

把 `registry.json` 与 `registry.json.sig` 放在同一目录发布（GitHub Pages、对象存储或任意静态站点均可），地址写入 `registry.rs` 的 `OFFICIAL_REGISTRY`。

- 小助手每小时刷新一次清单；签名无效、公钥不受信任、版本低于上次接受的版本时拒绝，继续使用上次的清单。
- 清单生成超过 30 天会告警，请至少每月重新签发一次（内容不变也可以，版本号会更新）。

### 2.4 节点加入与退出

1. 运营者按 §3 部署节点，运行 `xseed-node manifest https://<域名>` 得到清单条目，提交到 `nodes/`；
2. 维护者检查：域名可访问、`/.well-known/xseed` 返回的 `node_id` 与条目一致、`operator` 的权重合计不超过 30%；
3. 重新 build、sign、发布。新节点按 `since` 在 14 天内把权重从 10% 逐步提高到 100%。
4. 退出：删除对应文件后重新发布。

## 3. 部署社区节点

需要：1 核 1 GB 的 Linux 服务器、一个解析到它的域名、开放 80 / 443 端口、Docker。

```sh
mkdir xseed-node && cd xseed-node
curl -LO https://raw.githubusercontent.com/aidever/xseed/main/deploy/node/compose.yml
curl -LO https://raw.githubusercontent.com/aidever/xseed/main/deploy/node/Caddyfile
curl -L -o .env https://raw.githubusercontent.com/aidever/xseed/main/deploy/node/.env.example
vi .env                                    # 填写 XSEED_DOMAIN 与 XSEED_REGISTRY
docker compose up -d
docker compose exec node xseed-node manifest "https://$(grep XSEED_DOMAIN .env | cut -d= -f2)"
```

首次启动会在 `node-data/` 生成节点密钥 `node.key` 与默认配置 `xseed-node.toml`。请把 `trust_proxy = true` 写入配置（见 `deploy/node/xseed-node.toml.example`）后 `docker compose restart node`，这样限流按真实 IP 计算。

- **备份 `node-data/node.key`**：节点 ID 由它派生，丢失后需要重新提交清单条目。
- 节点重启时写入并载入快照 `snapshot.cbor`，登记数据不丢失；小助手会自动重连。
- 节点只保存不透明的指纹登记与信箱，不保存任何站点、种子或用户信息；默认 info 级别日志不记录客户端 IP。
- 容量参考：1 核 1 GB 约服务 1 万个在线小助手（03 §7.1）。

## 4. 发布检查清单

1. `cargo test --workspace`、`cargo clippy --workspace -- -D warnings` 通过；
2. 端到端：两个节点 + 至少两个小助手，覆盖 qBittorrent 与 Transmission，走通“发现 → 答题 → 下载 → 校验 → 做种”；
3. `OFFICIAL_REGISTRY`、`OFFICIAL_KEYS` 已填写，官方清单已签名发布且能被新版本验证；
4. 更新 README 进度与 [开发计划](04-开发计划.md)；
5. 打标签发布，确认 Release 附件与镜像标签齐全。
