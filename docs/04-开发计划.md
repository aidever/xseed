# xseed 开发计划

| 项目 | 内容 |
|---|---|
| 依据 | [概要设计](02-概要设计说明书.md)、[详细设计](03-详细设计说明书.md)、[页面设计稿 v3](ui/README.md) |
| 原则 | 每个里程碑都能独立运行、可测试；先本机、后网络；能用简单方案的不用复杂方案 |

## 里程碑

| 里程碑 | 目标 | 交付 | 状态 |
|---|---|---|---|
| M1 本机可用 | 装上就能看到“我的库”：连下载器、识别站点、同步 PT-depiler 凭证 | `xseed-core`：种子解析、指纹、桶、HRW、工作量证明、tracker 主机规范化、站点识别、passkey 与种子编号提取；`xseed-agent`：SQLite、凭证加密、管理员登录、qB / TR 适配器、清单扫描、PT-depiler WebDAV 接收端、Web UI（星轨设计）首次向导与五个页面；Dockerfile、CI | 已完成 |
| M2 辅种网络 | 小助手能连上社区节点并登记、查询，确认谁有同款 | `xseed-node`（信箱、代号、桶索引、两跳网关、节点间转发、限流、快照）；`xseed-transport`（消息格式、HPKE 两跳封装、鉴权与签名、探测标签、节点客户端）；agent `network` 模块（入口节点选择、信箱长连接、每周代号、分散登记、查询与探测、回应探测）；多节点集成测试 | 已完成 |
| M3 会员答题 | 两个小助手之间完成“询问 → 答题 → 告知” | `xseed-session`（Noise、状态机、通道绑定）；题库与答题缓存；`responder` / `requester`；试运行展示真实可辅种数 | 已完成 |
| M4 自动加种 | 拿到种子编号后自动下载、核对、加入、观察 | `jobs` 状态机、站点下载地址推导与限速、每日配额、失败原因、撤回全部；辅种记录五步进度轨接真实数据 | 已完成 |
| M5 发布 | 普通用户能装上 | 注册中心工具与签名、官方节点部署、Docker 多架构镜像、Windows 托盘、征求意见稿同步 2.0 | 未开始 |

## M1 说明

- 网络相关的数字（今日辅种、漏斗、热力格）在 M1 显示为空状态，文案说明“辅种网络将在后续版本开放”，不伪造数据。
- 星轨图在 M1 用真实的站点与本机种子数绘制，光束全部为静止状态。
- 试运行在 M1 只展示本机清单统计（种子数、站点、可登记为持有者的种子数），不展示可辅种数。

## M1 验收记录（2026-11-09）

- 单元测试：`xseed-core` 18 个、`xseed-agent` 13 个，全部通过；`cargo clippy -D warnings` 无告警。
- 端到端：本机 qBittorrent 5.1.0 + 5 个测试种子（3 个私有站、1 个公共种子、2 个内容相同的跨站种子）：
  - 向导：设置密码 → 测试连接（识别版本与已完成种子数）→ 全量扫描 → 站点勾选 → 试运行确认；
  - 识别：3 个站点按 tracker 主机识别、passkey 自动入库、公共种子归为“不参与”、跨站同内容计入“已在多站做种”；
  - PT-depiler：用 openssl 生成的加密备份经 WebDAV `PUT` 同步 2 个站点与 2 个 Cookie，重扫后种子归入 PT-depiler 中的站点名；错误文件名 403、错误口令 401；
  - 安全：非本机 Host 403、跨站 Origin 403、缺 CSRF 403、未登录 401、登录连续失败第 6 次 429。
- 页面截图（桌面 1440、手机 390、浅色）见 [ui/m1](ui/m1/)。

## M1 与详细设计的偏差

- `local_torrents` 主键改为 `(downloader, hash)`（下载器自身的 hash 字符串），并增加 `reason` 列与 `unknown_site` 状态，详见 03 §3.1。
- PT-depiler 备份格式按其源码修正：`manifest.files` 为对象；加密口令为 `md5Hex(密钥)` 前 16 位，详见 03 §1.12.2。
- Web UI 的 CSP 允许内联样式（`style-src 'unsafe-inline'`），脚本仍只允许同源文件。

## M2 验收记录（2026-11-09）

- 单元测试与集成测试共 40 个，全部通过；`cargo clippy -D warnings` 无告警。新增：
  - `xseed-transport`：消息往返、代号签发 / 解析 / 过期、HPKE 两跳封装（含 512 字节填充、目标不符时无法解开）、信箱 MAC 与节点签名、探测标签；
  - `xseed-node` 集成测试（进程内 3 个节点）：两跳登记到 HRW 两个所有者、工作量证明不能重放、跨节点查询、跨节点探测与回应、伪造回信地址被拒、目标离线返回 `mailbox_offline`、错误的信箱凭证 / 未签名转发 / 无效工作量证明被拒；
  - agent：只回应 SFP 匹配、站点开启且允许“帮别人找到辅种”的探测。
- 端到端：2 个节点（`xseed-node` 进程）+ 2 个小助手（同一个 qBittorrent 5.1.0）：
  - 两个小助手各登记 4 个持有者代号 × 2 个副本；查询后互相探测，各自确认 4 个本机种子在社区里有同款；
  - 把小助手 B 固定到节点 2 后，自动换新入口并重新登记；节点 1 ↔ 节点 2 各转发 20 个信封，无失败；旧入口的连接随即关闭；
  - 重启节点 2：写入并载入快照（2 个信箱、12 条登记），小助手 B 自动重连。
- 页面截图见 [ui/m2](ui/m2/)：概览“发现同款文件”显示真实数字，设置页可选择入口节点、填写节点清单。

## M2 与详细设计的偏差

- 信箱 `secret` 由节点私钥按 `slot_token` 派生，节点不保存（原设计“只保存 H(secret)”无法校验 HMAC），见 03 §2.1。
- 信箱请求 MAC 统一为 `HMAC(secret, "xseed/req/v1" ‖ path ‖ 0x00 ‖ ts ‖ H(body))`；节点间签名放在 `X-Xseed-Node / Ts / Sig` 请求头中。
- 代号中的周序号为自 Unix 纪元起的整周数，而不是 ISO 周。
- 节点只监听明文 HTTP（默认 7800），TLS 由反向代理负责；节点清单在 M2 为未签名 JSON，签名在 M5。
- 桶节点只接受自己是 HRW 所有者的桶的登记。
- 探测在 M2 完成（原计划放在 M3 会话中），用来给出“发现同款文件”的真实数字；Noise 会话、答题、告知编号仍在 M3。

## M3 验收记录（2026-11-09）

- 单元测试与集成测试共 46 个，全部通过；`cargo clippy -D warnings` 无告警。新增 `xseed-session`：完整握手与问答、内容不同无法握手、转交他人答案在本会话下校验失败、全部消息往返且填充到 256 字节、答案各字段以 0x00 分隔不会混淆；agent：可注册域名判断。
- 端到端：2 个节点 + 2 个小助手 + 2 个 qBittorrent 5.1.0 + 模拟站点（X、Y 两站，NexusPHP 风格 `download.php?id=&passkey=`）：
  - A 持有 X#2001、Y#3001（同一内容），B 持有 Y#3001、X#2002；B 发现同款后向 X 站询问；
  - 第一次询问时 A 的 X 站题库为空，回 `NOT_MEMBER` 并在后台补题（经 http 从站点下载随机编号的种子，新增 4 题）；
  - 再次询问：探测 → Noise 握手 → `ASK` → `CHAL{#1453}` → B 用自己的 passkey 下载 #1453 并作答 → `OFFER{#2001}`；B 收到的 info_hash 与大小和本机一致，记入 `offers`，答题缓存与 A 的题目使用次数随之更新；
  - 辅种记录页显示“已拿到种子编号，等待加种”，概览漏斗 02“会员题通过”显示真实数字。
- 页面截图见 [ui/m3](ui/m3/)。

## M3 与详细设计的偏差

- 答题 MAC 中的站点使用 `SiteRef` 字符串形式（`site:…` / `host:…`），字段间以 0x00 分隔，不使用 CBOR 编码，见 03 §1.6.3。
- 下载种子不跟随任何重定向；只有 tracker 本身为 http 的站点才会尝试 http，见 03 §1.11.3。
- 新增 `asks` 表：同一（内容，站点）7 天内不重复询问，单次最多问 5 个持有者，拿到 `OFFER` 即停，见 03 §1.5.3、§3.1。
- 题库补题只在站点可访问时计入每周次数；`ASK` 时题库为空先回 `NOT_MEMBER` 再后台补题。
- “试运行展示真实可辅种数”改为在概览漏斗与辅种记录中展示真实的发现数与拿到编号数；拿到编号后的下载、核对、加种在 M4。

## M4 验收记录（2026-11-10）

- 单元测试与集成测试共 51 个，全部通过；`cargo clippy -D warnings` 无告警。新增：qB / TR 状态与 tracker 汇报解析、tracker 失败信息归类、加入布局（qB 无子文件夹、TR 改根目录名、单文件）、五步进度轨的步数。
- 端到端：2 个节点 + 3 个小助手 + 2 个 qBittorrent 5.1.0 + 1 个 Transmission 4.1.0-beta.2 + 模拟站点（新增 tracker `announce.php`，可切换为返回 `Unregistered torrent`）：
  - **qB**：B 拿到 X#2001 → 用自己的 passkey 下载 → 核对 info_hash、指纹、tracker 主机 → 原种子 `C1.Y` 仍完整 → 以停止状态、无子文件夹布局加入 `files/C1.Y`（根目录名 `C1.X` ≠ `C1.Y`），进度 100%，带 `xseed` 标签 → 启动 → tracker 正常 → 做种中；
  - **全部移除**：移除 1 个，原种子与文件不受影响；
  - **tracker 拒绝**：站点 tracker 返回 `Unregistered torrent` 时，加入后被识别为 `tracker_unregistered` 并自动移除（文件未动）；恢复后在辅种记录点“重试”，重新加入并做种；
  - **TR**：C（Transmission）经探测、答题拿到 X#2001（途中其他持有者正确回答 `NONE`），加入后 `torrent-rename-path` 把根目录名改为 `C1.Y`（只改元数据），显式校验通过后启动，tracker 返回 Success，做种中。
- 页面截图见 [ui/m4](ui/m4/)：概览“+1”主视觉、今日有新增的站点光束流动、五步漏斗全部为真实数字、最近辅种与 12 周热力格；辅种记录的做种中 / 失败（红点、§5.3 文案、重试）；站点卡片“由 xseed 辅入”。

## M4 与详细设计的偏差

- 新种子一律以停止状态加入，观察时确认进度 100% 后才启动（设计为加入后立即启动再检查），避免数据不完整时下载器写入已有文件。
- qB 多文件种子统一使用 `content_path` + 无子文件夹布局，不再区分根目录名是否相同，见 03 §1.10。
- TR 加入后显式校验（TR 没有“跳过校验”）。
- “对端计入失败”未实现：查询方不保留对端身份（回信代号每次新建），无法对对端计分；`ih_mismatch` / `sfp_mismatch` 只让本任务失败。
- 抽查（`sample.enabled`）未实现，留到后续版本；默认配置下不读数据文件，与设计一致。
- `jobs` 表增加 `new_hash`、`not_before` 两列；失败原因增加 `site_unreachable`，见 03 §3.1、§9.3。
- 统计按 UTC 日期计“今天”。
